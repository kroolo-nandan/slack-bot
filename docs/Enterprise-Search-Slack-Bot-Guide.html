Enterprise Search Slack Bot — Technical Guide

Version 1.0 • 2025-08-14

The Enterprise Search Slack Bot enables users to search, discover, and interact with enterprise content directly from Slack. It integrates with a FastAPI backend and renders rich, interactive Slack messages using Block Kit. This guide covers capabilities, end-to-end flow, intents, roles, authentication, middleware usage, endpoints, formatting, and troubleshooting.

Capabilities

  • Search documents via FastAPI (POST /api/search) and display rich results.
  • Suggested documents personalized by user/company context (POST /api/suggested-documents).
  • Trending documents with interactive actions (Why this?, Search similar) and pagination (POST /api/trending-documents).
  • Company context selection per Slack user and channel using SlackSessionModel.
  • Admin tool requests redirection to Enterprise Search console.
  • General small talk without authentication.

Architecture & Flow

  1. Slack Event: Mentions or DMs handled in app.js.
  2. Pre-checks: Auto-join, quick NLP general intent, redirect admin-tool phrases.
  3. Authentication & Context: Email via users.info, requireUserAuthentication, company selection via SlackSessionModel.
  4. Intent Processing: queryHandler.processQuery() dispatches actions.
  5. API Calls: apiService.callAPI() whitelists params, adds RBAC fields.
  6. Formatting: formatResponse() maps to Block Kit via formatter.js.

Intents

  • general: Greetings/help (no auth), conversational response.
  • callSearchApi / search: POST /api/search with { query, limit?, company_id, user_email }.
  • getSuggestedDocuments: POST /api/suggested-documents with RBAC-only body.
  • getTrendingDocuments: POST /api/trending-documents with RBAC-only body.
  • analytics (optional): Only if backend exposes endpoints; otherwise returns 404.

Roles & Permissions

User

  • Run searches and view suggestions/trending within selected company.
  • Company context stored per-channel.

Admin

  • Manages connectors/tools in the Enterprise Search console.
  • Bot redirects admin actions to web console.

Authentication & Company Context

  • Email extraction via Slack users.info; fallback from RBAC config.
  • Middleware: requireUserAuthentication ensures access & company selection; persists in SlackSessionModel.
  • Skip middleware case: general intent replies without hitting secured endpoints.

Slack Formatting

  • Search: Header with count/time; up to 5 results with title, preview, Open button, platform, score.
  • Suggested: Header with count; items with preview, platform, file type, score, item reason; optional global reason.
  • Trending: Items with preview and context; actions: Why this?, Search similar; Show more pagination. Defensive checks to avoid invalid_blocks.

Configuration

  • FASTAPI_BACKEND_URL — Host only (no /api suffix).
  • DEFAULT_COMPANY_ID — Fallback company.
  • Slack: SLACK_BOT_TOKEN, SLACK_SIGNING_SECRET, optional SLACK_APP_TOKEN.
  • Optional ES_DASHBOARD_URL for redirect buttons.

Key Files

  • app.js — Events, auth, company selection, actions for trending interactivity.
  • src/handlers/queryHandler.js — Intent dispatch and API calls.
  • src/services/apiService.js — Axios client, RBAC fields & validation.
  • src/utils/formatter.js — Block Kit rendering.
  • src/middleware/authenticateUser.js — Access & company selection.
  • src/models/SlackSession.js — Session persistence.

Troubleshooting

  • 422: Only whitelisted params; ensure company_id and user_email.
  • 404: Correct endpoints; no double /api.
  • invalid_blocks: No placeholder URLs, no action_id on URL buttons, truncate previews.
  • Port in use: Change PORT or free 3000.
